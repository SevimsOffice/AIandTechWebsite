Section 01

The Plan > Build > Test Framework

Most people who try to vibe code end up stuck in an endless loop of bugs. That's because they skip planning and jump straight into prompts. The framework that actually works is simple: plan your idea first, build it step by step, and test each phase before moving on. AI is a force multiplier, not an autopilot. Structure beats heroics.

⚠ THE VIBE CODE DEATH LOOP

This is what happens when you skip planning: you prompt, get errors, paste the errors back, get more errors, and spend hours going in circles. Everything in this guide exists to help you avoid that loop.

Section 02

Your Tool Stack

Before you start building, here's what you need. You don't need all of these, but this is the stack we use and recommend at AI and Tech.

1
Claude (claude.ai)

For planning, scoping ideas, and building your PRD. This is where you do all your thinking before you start coding.

2
Claude Code

Your AI code builder. This is where the actual building happens. Install: npm install -g @anthropic-ai/claude-code

3
Stitch (Google)

AI design tool for building professional UIs. Use this to make your app look like a real agency built it instead of default AI styles.

4
GitHub

Free version control. Claude Code handles git for you, but you need an account to save your code and deploy.

5
Vercel or Netlify

Free hosting to put your app online. Connect your GitHub repo and it auto-deploys when you push code.

6
Supabase

Free database and authentication if your app needs user accounts or data storage. Claude Code sets this up for you.

PICK ONE CODE BUILDER

There are many options: Claude Code, Cursor, Replit, Lovable, Base44. They all work. But pick ONE tool for the entire project. Switching tools mid-build creates more problems than it solves. We use Claude Code for everything.

Section 03

Step 1: Scope Your Idea (Build a PRD)

Before you touch Claude Code, open regular Claude and scope your idea. Tell Claude to think like a senior engineer and to interview you to understand the product you want to build. Let Claude ask you questions about what you're trying to create, who it's for, and what features you need.

After you scope the project, ask Claude to create a Product Requirements Document (PRD). This is your master plan — it maps out every feature, the tech stack, integrations, and how everything connects. This is the most important step and what separates apps that work from apps that break.

Prompt 1 · Scope & PRD

You are an expert product and SaaS builder, and a senior engineer. Your role is to help me scope out a new product. Please interview me and ask as many questions as you need to fully understand what I want to build. Then help me create a full product requirement document. I also need you to suggest the best tech stack, integrations, and features that we should build.

Work with Claude to refine the PRD until it covers everything. Get it to recommend features you haven't thought of, suggest the right integrations, and map out the full scope. Then ask Claude to break it down into versions so you're not trying to build everything at once:

Prompt 2 · Version Roadmap

Can you please take the PRD we just made and break it down into a clear development roadmap with defined scopes for a V1, V2, etc. Please ask me any questions you need to confirm my preferences.

Finally, turn the V1 plan into a structured task list. This is what you'll feed into Claude Code:

Prompt 3 · Task List

Can you please take the V1 plan and break it down into a structured task list that I can feed into my AI code builder so that I can get the highest quality output.

WHY THIS STEP MATTERS

Planning with reasoning models leads to higher quality code and gives the AI more context to understand the end goal. The PRD is like giving a contractor blueprints before asking them to build a house. Without it, Claude is guessing at what you want — and that's where bugs come from.

Section 04

Step 2: Build in Claude Code (Plan Mode)

Take your PRD and task list into Claude Code. Before you start building, set the stage with this prompt. This is critical — it tells Claude how to act and prevents it from taking shortcuts that break things later:

Prompt 4 · Set the Stage

When we are building please act as a senior level developer who only builds robust, secure, efficient code and follows best practices. Please ensure when suggesting tasks that they follow these instructions to reduce technical debt, and only solve root cause issues if bugs pop up.

Then give Claude Code your PRD and enter plan mode. Ask Claude to give you a step-by-step build plan with testing and evaluation at each stage. Follow the task list one phase at a time.

  • Enter plan mode and give Claude your PRD — it builds the implementation plan for you
  • Ask for a step-by-step build plan with testing and evaluation at each stage
  • Follow the task list one phase at a time — do NOT skip ahead
  • Test each phase before moving to the next. This is non-negotiable.
  • Read what Claude suggests before approving it. If you don't understand, ask Claude to explain.
  • If something doesn't make sense, go back to your PRD and ask Claude if the suggestion aligns with the product plan
  • Periodically re-set the stage to make sure Claude is still following best practices
HOW AI CODING WORKS

You give Claude prompts. Claude writes the code, tells you what it's doing, and asks for permission before making changes. Read what it suggests before approving. If you don't understand what it's suggesting, go back to your project folder in regular Claude and ask if that suggestion makes sense based on the PRD.

Section 05

Step 3: Test and Polish

Work with Claude to start building. Run your app after every phase, fix bugs as they come up, and when you're ready to make it look professional use a tool like Stitch to design the user interface so it doesn't look like every other AI-built app.

  • Test every feature after each build phase — never batch testing at the end
  • Copy error messages and paste them back to Claude to fix bugs
  • If something fails 3 times with the same approach, ask Claude to try a completely different solution
  • When the core functionality works, use Stitch to design a polished UI
  • Ask Claude to help you deploy to Vercel or Netlify when you're ready to go live
THE UI PROBLEM

90% of vibe-coded apps look the same — purple gradients, default fonts, generic layouts. Using Stitch to design your interface makes your app look like it came from a real agency. This is the difference between a side project and something you can show to clients or customers.

Section 06

Common Mistakes to Avoid

These are the mistakes almost everyone makes at the start. Avoiding these will save you hours.

  • Skipping the PRD — this is the #1 cause of the death loop. Always plan first.
  • Trying to build everything at once — stick to V1 scope. Features can wait for V2.
  • Not testing between phases — if Phase 1 is broken, Phase 2 will be worse. Fix before moving on.
  • Switching tools mid-project — pick Claude Code (or whatever tool) and stick with it for the entire build.
  • Not setting the stage — without the stage-setting prompt, Claude takes shortcuts, hardcodes values, and creates technical debt.
  • Ignoring what Claude suggests — read the suggestions. If you don't understand, ask Claude to explain before approving.
  • Prompting too vaguely — "build me an app" won't work. The more specific your PRD and task list, the better the output.
Section 07

Ideas to Get Started

Not sure what to build? Here are three ways to find ideas:

1
Audit your day and find manual processes

Anything you do on a computer more than twice a week is a candidate (example: a tax receipt organizer, a client invoice tracker).

2
Solve a problem for someone you know

Build a tool for a friend, partner, or colleague (example: a shopping list app, a client proposal generator, an appointment scheduler).

3
Look for ways to add value in your industry

Tools that save time or money are easiest to validate (example: a roofing quote calculator, a restaurant inventory counter, a lead intake form).

START SMALL

Your first app doesn't need to change the world. Build something simple that solves one problem. A calculator, a form, a dashboard. Get the process down first, then tackle bigger projects. The framework is the same regardless of complexity.

Section 08

Worked Example: A Client Proposal Generator

Here's how the framework plays out on a real, practical project — a web app that turns a short briefing into a polished client proposal. Follow the same five moves for any app you build.

1
PRD in Claude

Tell Claude you want a proposal generator. Claude interviews you about the target users (freelancers, agencies), the core features (briefing form, AI-drafted sections, PDF export), and the tech stack. You settle on Next.js, Supabase for the database, and the Claude API for drafting proposal sections.

2
V1 Scope

Claude breaks the PRD into V1 (core flow — fill the briefing, generate sections, export PDF) and V2 (saved templates, client accounts, e-signature). You focus only on V1 first.

3
Task List to Claude Code

Take the structured task list into Claude Code, set the stage with the senior developer prompt, and enter plan mode. Claude builds the implementation plan in phases: project setup, database, briefing form, AI drafting, PDF export, deployment.

4
Build Phase by Phase

Follow each phase, testing after every one. When a bug appears — say the PDF export breaks on long proposals — copy the error, paste it back to Claude, and let it fix the root cause. A focused project like this typically takes a few days of sessions.

5
UI Polish with Stitch

Once the core works, use Stitch to design the interface: custom color scheme, clean typography, professional layout. The app goes from looking like a homework project to looking like a real product.

Section 09

Troubleshooting Guide

When things go wrong (and they will), here's how to handle the most common situations.

CLAUDE IS STUCK IN A LOOP

If Claude keeps trying the same fix and it keeps failing, say: "This approach isn't working. Please suggest a completely different solution to this problem." Sometimes Claude needs a hard reset on its approach.

THE APP WORKS LOCALLY BUT BREAKS WHEN DEPLOYED

This is usually an environment variable issue. Ask Claude: "Can you check that all environment variables are properly set for production deployment?" Make sure API keys and database URLs are configured in your hosting platform (Vercel, Netlify).

CLAUDE MADE CHANGES THAT BROKE SOMETHING ELSE

Say: "The last change broke [describe what's broken]. Can you revert that change and try a different approach that doesn't affect [the thing that broke]?" Claude can use git to undo changes.

YOU DON'T UNDERSTAND WHAT CLAUDE IS SUGGESTING

Don't just approve it. Go back to regular Claude, paste the suggestion, and ask: "Based on my PRD, does this suggestion make sense? Explain it to me like I'm not technical." Never approve code you don't understand.

THE APP LOOKS GENERIC / LIKE AI BUILT IT

This is the Stitch moment. Don't try to fix the design with prompts in Claude Code. Use Stitch to generate a professional design system, then apply it. It's faster and the results are dramatically better.
